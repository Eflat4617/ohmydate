## 1. 개요

### OhMyDate는 무엇을 하나요

OhMyDate는 **적응형 AI 개인 플래너**예요. 할 일을 적어 두면 필요한 것만 물어보고, AI가 단계로 나눈 초안을 만들고, 내 가용 시간과 약속을 피해 **서로 다른 일정안**을 2–3개 보여 줘요. 내가 고른 일정만 실제로 반영되고, 집중 세션의 실제 시간을 보고 추정을 조금씩 내게 맞춰 가요. 일정이 어긋나면 최소한만 고친 **재계획 제안**을 보내지만, 승인하기 전에는 아무것도 바뀌지 않아요.

흐름은 이렇게 한 바퀴 돌아요.

```text
인박스에 적기 → 계획 마법사(질문·AI 단계 초안) → 일정안 비교·확정 → 오늘·집중 → 회고 → 내 패턴 → (필요하면) 재계획
```

작업(할 일) 자체는 오픈소스 작업 관리 도구 **Vikunja** 위에 저장되고, OhMyDate는 그 위에서 계획·일정·집중·노트를 다뤄요.

- 일정 계산(후보 만들기, 축소·재배치, 재계획)은 AI가 아니라 **규칙 기반 스케줄러**가 해요. 그래서 AI 비용이 들지 않고, 같은 입력이면 같은 결과가 나와요.
- AI는 계획 마법사에서 **비슷한 작업 찾기**와 **단계 초안 만들기**에만 써요. 결과는 항상 “초안”이고, 내가 고치고 승인해야 반영돼요.

### GU-1은 무엇을 위한 단계인가요

GU-1은 **M7(자체 백엔드로 교체) 전에, 지금 버전을 직접 써 보고 확인하는 관문**이에요. 지금까지 만든 기능(M1–M6)을 실제 내 데이터로 며칠 써 보고, 계획 품질·추정·한국어 문구·속도·AI 쓸모를 판단해 피드백을 주시면 돼요. 사용자 확인 전에는 M7 작업을 시작하지 않아요.

| 지금 써 볼 수 있어요 (GU-1 범위) | 아직 아니에요 (범위 밖) |
|---|---|
| 인박스·프로젝트(작업은 Vikunja에 저장) | **M7 자체 백엔드(Native)** — Vikunja를 대체하는 작업 저장소 |
| 계획 마법사: 질문, AI 단계 초안, 직접 작성 모드 | 홈서버 배포·원격 접속(휴대폰 포함) — 이 노트북 안(127.0.0.1)에서만 |
| 가용 시간·약속, 일정안 후보 비교·편집·확정 | 파일 첨부 업로드(“파일 이름 (선택, 업로드는 곧 지원)”) |
| 오늘·집중 세션·회고, 내 패턴(추정 학습) | 전체 검색(검색 창은 아직 안내 문구만 있어요) |
| 블록 고정, 재계획 제안(승인/거절) | 장기 계획(먼 미래 마일스톤), 여러 사용자 협업 |
| 노트(Markdown)와 노트를 근거로 한 AI 초안 | 화면에서 하는 데이터 내보내기·계정 삭제 |
| 적응형 레이아웃, 앱 안 알림(+선택: 브라우저 푸시) | 비밀번호 재설정 화면 |

### 데이터는 어디에 있나요

모든 서비스는 **이 노트북의 127.0.0.1(루프백)에만** 열려 있어요. 같은 와이파이의 다른 기기에서도 접속할 수 없어요.

| 무엇 | 어디 | 주소/포트 |
|---|---|---|
| 웹 화면 | 이 노트북에서 실행되는 웹 프로세스 | http://127.0.0.1:5180/ |
| API | 이 노트북에서 실행되는 API 프로세스 | http://127.0.0.1:3100 |
| 작업(할 일) | Vikunja → PostgreSQL `vikunja` DB | http://127.0.0.1:3466 (Vikunja 화면, 선택) |
| 계획·일정·집중 기록·노트·설정 | PostgreSQL `planner` DB | 127.0.0.1:55442 |
| DB 파일 | Docker 볼륨 `ohmydate-local_pgdata` | — |
| Vikunja 첨부 파일 | Docker 볼륨 `ohmydate-local_vikunja-files` | — |
| 비밀 파일(DB 비밀번호, 세션 비밀, Vikunja 토큰 등) | `deploy/secrets/local/` (폴더 0700, 파일 0600, git 제외) | — |
| 실행 로그·PID | `.local/logs/`, `.local/run/` | — |
| 오프라인 중 집중 기록 | 브라우저 저장소(다시 연결되면 자동 업로드) | — |

노트북 밖으로 나가는 데이터는 두 가지뿐이에요.

1. **AI 호출**(동의했을 때만): 계획 마법사 입력과 허용한 노트 일부가 OpenCode Go 게이트웨이로 가요. 자세한 내용은 [4장](#4-ai-사용-동의와-비용).
2. **브라우저 푸시**(직접 “푸시 알림 켜기”를 눌렀을 때만): 브라우저 회사의 푸시 서비스를 거쳐요.

> **중요 — 비밀 디렉터리와 볼륨은 한 쌍이에요.**
> `deploy/secrets/local/` 안의 `postgres.env`에 DB 비밀번호가 있어요. 이 폴더를 잃어버리면(예: `git clean -fdx`, 작업 폴더 삭제) **기존 DB에 다시 접속할 수 없어요.** 백업할 때는 비밀 디렉터리와 DB를 **항상 같이** 백업하세요. 폴더가 없는데 볼륨이 남아 있으면 `local:status`가 경고해요.

### 백업하는 방법

저장소 루트에서 실행해요. 2번은 `sudo` 비밀번호를 물어요. 스택(PostgreSQL·Vikunja)은 켜져 있어야 해요.

```sh
# 0) 앱을 멈추고 백업 폴더를 만들어요 (저장소 밖, 나만 읽을 수 있게)
corepack pnpm local:stop
mkdir -p ~/ohmydate-backup && chmod 700 ~/ohmydate-backup

T=$(date +%F-%H%M%S)

# 1) 비밀 디렉터리 (권한 그대로 묶어요)
tar -czf ~/ohmydate-backup/secrets-$T.tgz -C deploy/secrets local

# 2) DB 전체(planner + vikunja)를 한 파일로 — 임시 파일에 쓰고, 성공했을 때만 이름을 바꿔요
sudo docker compose -p ohmydate-local --env-file deploy/local/local.env -f deploy/local/compose.yaml \
  exec -T postgres pg_dumpall -U ohmydate > ~/ohmydate-backup/pg-$T.sql.tmp \
  && mv ~/ohmydate-backup/pg-$T.sql.tmp ~/ohmydate-backup/pg-$T.sql

# 2-1) 매번 확인: 파일이 비어 있지 않고 마지막 부분에 완료 표시가 있어야 해요
tail -n 8 ~/ohmydate-backup/pg-$T.sql | grep -q "PostgreSQL database cluster dump complete" && echo "DB 백업 OK"

# 3) 백업 파일도 나만 읽게
chmod 600 ~/ohmydate-backup/*

# 4) 다시 시작
corepack pnpm local:start
```

- 백업 파일에는 내 작업·노트·계정 정보가 그대로 들어 있어요. 클라우드 공유 폴더나 저장소 안에 두지 마세요.
- Vikunja 화면에서 직접 첨부를 올리지 않았다면 `vikunja-files` 볼륨은 비어 있어요(OhMyDate에는 아직 업로드 기능이 없어요).
- **복원**은 비밀 디렉터리와 DB를 함께 되돌려야 해서 코디네이터와 같이 진행해 주세요. 데이터 초기화(볼륨 삭제)도 코디네이터 작업이에요. `local:stack down`은 볼륨을 지우지 않아요(`-v`를 붙여도 무시해요).
- DB 백업 명령은 코디네이터가 실제 로컬 스택에서 실행해 확인했어요(2026-11-12). 그래도 **매번** `DB 백업 OK`가 나오는지 확인해 주세요. 실패하면 `.sql.tmp` 파일만 남고 이전 백업은 그대로예요.

## 2. 처음 설치

### 준비물

- Node 24 이상, `corepack` (전역 설치나 `corepack enable`은 필요 없어요. 모든 명령은 `corepack pnpm …`으로 실행해요).
- Docker가 설치된 이 노트북의 `sudo` 권한(스택 시작 때 한 번 물어요).
- **DeepSeek(OpenCode Go) API 키 파일** — 아래 “API 키 파일” 참고.
- 브라우저: **Chrome 또는 Firefox** (Safari/WebKit 계열은 로그인이 안 돼요 → [7장](#7-알려진-제한)).

모든 명령은 **저장소 루트**에서 실행해요.

```sh
cd <저장소 루트>                 # 예: git 저장소 최상위 폴더
corepack pnpm install            # 처음 한 번, 그리고 코드가 바뀐 뒤 (의존성 설치)
```

### API 키 파일

- 기본 위치는 `<저장소 루트>/deepseek_api_key.txt`예요(git에서 제외된 파일).
- 다른 곳에 두려면 `deploy/local/local.env`의 `LLM_API_KEY_FILE=` 값을 바꿔요. 상대 경로는 저장소 루트 기준이고, 셸 환경 변수 `LLM_API_KEY_FILE`이 있으면 그 값이 이겨요.
- 권한은 반드시 **600**(나만 읽기·쓰기)이어야 해요. 그룹·다른 사용자 권한이 있으면 시작을 거부해요.

```sh
chmod 600 deepseek_api_key.txt
stat -c '%a %n' deepseek_api_key.txt     # "600 deepseek_api_key.txt" 이면 OK (내용은 출력하지 않아요)
```

- 로컬 스크립트는 키 파일의 **존재와 권한만** 확인하고 내용을 읽거나 출력하지 않아요. 키는 API 프로세스만 읽어요.
- **키를 채팅·이슈·피드백·스크린샷 어디에도 붙여 넣지 마세요.** `cat`으로 화면에 띄우지도 마세요.

### 설치 순서 (처음 한 번)

```sh
# 1) 로컬 비밀 파일 만들기 (여러 번 실행해도 안전, 값은 출력하지 않아요)
corepack pnpm local:secrets

# 2) PostgreSQL + Vikunja 스택 시작 (sudo 비밀번호를 물어요)
corepack pnpm local:stack up

# 3) 계정 만들기: 이메일, 비밀번호(두 번, 화면에 안 보여요), 시간대
corepack pnpm local:setup

# 4) 빌드(필요할 때만) 후 API + 웹 시작
corepack pnpm local:start

# 5) 브라우저(Chrome/Firefox)에서 열기
#    http://127.0.0.1:5180/
```

#### 1) `local:secrets` — 잘 되면

```text
[local] 비밀 디렉터리: <저장소 루트>/deploy/secrets/local
[local] 새로 만든 파일: postgres.env, vikunja.env, push.key, llm-session-secret
[local] 기존 파일 유지: 없음
[local] 값은 출력하지 않습니다.
```

두 번째부터는 “새로 만든 파일: 없음”, “기존 파일 유지: …”로 나와요. 기존 파일은 절대 덮어쓰지 않아요.

#### 2) `local:stack up` — 잘 되면

```text
[local] 실행: sudo docker compose -p ohmydate-local --env-file <저장소 루트>/deploy/local/local.env -f <저장소 루트>/deploy/local/compose.yaml up -d
[sudo] password for <사용자>:
```

그 뒤 docker가 컨테이너(postgres, vikunja-db-init, vikunja-files-init, vikunja)를 만들고 시작해요. 처음에는 이미지를 받느라 몇 분 걸릴 수 있어요. 상태 확인: `corepack pnpm local:stack ps`.

#### 3) `local:setup` — 묻는 것과 잘 되면 나오는 것

순서대로 물어요.

```text
[local] 비밀 디렉터리 준비 완료: …
[local] 대상: PostgreSQL 127.0.0.1:55442/planner · Vikunja http://127.0.0.1:3466
[local] 스택 상태를 확인하는 중입니다...
이메일: you@example.com
비밀번호:            ← 입력해도 화면에 보이지 않아요 (8자 이상)
비밀번호 확인:
[local] planner 마이그레이션을 적용하는 중입니다...
시간대 [Asia/Seoul]:  ← 그냥 Enter 를 누르면 이 컴퓨터의 시간대(보통 Asia/Seoul)를 써요
```

잘 끝나면:

```text
[local] 설정 완료
[local]  - 이메일: you@example.com
[local]  - planner owner id: …
[local]  - Vikunja 사용자: local-… (id …)
[local]  - Inbox 프로젝트 id: …
[local]  - 시간대: Asia/Seoul · locale: ko-KR
[local]  - API 토큰: 새로 발급 (만료 2027-…)
[local] 다음 명령: corepack pnpm local:start
[local] 로컬 앱이 이미 실행 중이라면 local:stop 후 local:start 로 재시작하세요.
```

- 여기서 정한 **이메일·비밀번호가 OhMyDate 웹 로그인 정보**예요. 같은 비밀번호로 Vikunja 계정(`local-…`)도 만들어져요.
- 같은 이메일로 다시 실행하면 아무것도 바꾸지 않아요(시간대·언어 설정도 그대로). 시간대는 나중에 웹의 “가용 시간” 화면에서 바꿀 수 있어요.

#### 4) `local:start` — 잘 되면

처음에는 빌드 때문에 1–3분쯤 걸려요.

```text
[local] 대상: PostgreSQL 127.0.0.1:55442/planner · Vikunja http://127.0.0.1:3466
[local] 실행 모드: NODE_ENV=production, LLM_PROVIDER=deepseek
[local] API 빌드 중...
[local] 웹 빌드 중...
[local] OhMyDate 로컬 실행 준비 완료: http://127.0.0.1:5180/
[local] API: http://127.0.0.1:3100 (로그: <저장소 루트>/.local/logs/api.log)
[local] 웹: http://127.0.0.1:5180/ (로그: <저장소 루트>/.local/logs/web.log)
```

#### 5) 첫 화면

http://127.0.0.1:5180/ 을 열면 “**OhMyDate에 로그인**” 화면이 나와요. 3단계의 이메일·비밀번호로 “로그인”하면 “인박스”가 열리고, 곧 “**AI 계획 도움을 쓸까요?**” 창이 떠요 → [4장](#4-ai-사용-동의와-비용).

> 주소는 꼭 `127.0.0.1`로 여세요. `localhost`나 다른 IP로 열면 로그인 쿠키가 따로 저장되거나 연결이 안 될 수 있어요.

### 자주 만나는 오류와 해결

| 이런 메시지가 나오면 | 원인 | 이렇게 하세요 |
|---|---|---|
| `먼저 coordinator가 deploy/local 스택을 올려야 합니다. 정확한 명령: cd … && corepack pnpm local:stack up …` (끝부분은 `local:start`에서는 `(postgres=down, vikunja=down)`, `local:setup`에서는 30초 기다린 뒤 `(PostgreSQL: …)`/`(Vikunja: …)` 형태) | PostgreSQL/Vikunja 스택이 꺼져 있어요 | `corepack pnpm local:stack up` 실행 후 `corepack pnpm local:stack ps`로 확인. 방금 켰다면 30초쯤 기다렸다 다시 시도 |
| `LLM API 키 파일 권한이 644 입니다. group/world 접근을 막아야 합니다. 정확한 명령: chmod 600 …` | 키 파일 권한이 넓어요 | 메시지에 나온 `chmod 600 <경로>`를 그대로 실행 |
| `LLM API 키 파일이 없습니다: …. deepseek_api_key.txt (또는 LLM_API_KEY_FILE)을 0600 으로 준비하세요.` | 키 파일 위치가 달라요 | 파일을 저장소 루트에 두거나 `deploy/local/local.env`의 `LLM_API_KEY_FILE`을 고쳐요 |
| ``로컬 비밀 파일이 없습니다: …. 먼저 `corepack pnpm local:setup` 을 실행하세요.`` | setup을 아직 안 했어요 | `corepack pnpm local:setup` |
| ``마이그레이션이 최신이 아닙니다: …. 먼저 `corepack pnpm local:setup` 을 실행하세요.`` | 새 코드에 DB 변경이 있어요 | `corepack pnpm local:setup`(같은 이메일·비밀번호) 후 `local:start` |
| ``API가 이미 실행 중인데 빌드가 필요합니다. `corepack pnpm local:stop` 후 다시 `local:start` 하세요.`` (또는 “웹이 …”, “… 프로세스가 현재 빌드보다 오래되었습니다.”) | 코드가 바뀌었는데 예전 프로세스가 돌고 있어요 | `corepack pnpm local:stop` → `corepack pnpm local:start` |
| `프로세스가 응답 전에 종료되었습니다 (pid …). 마지막 로그: …` | 포트 3100 또는 5180을 다른 프로그램이 쓰고 있거나 시작 중 오류 | 아래 표 밑의 `ss` 명령으로 누가 쓰는지 보고 그 프로그램을 끈 뒤 다시 `local:start`. 그래도 안 되면 `.local/logs/api.log`, `web.log` 마지막 줄을 확인 |
| `비밀번호가 서로 일치하지 않습니다.` / `비밀번호는 8자 이상이어야 합니다.` | setup 입력 문제 | `local:setup`을 다시 실행 |
| `Vikunja 사용자 등록/로그인에 실패했습니다. 같은 이메일의 사용자가 이미 있고 비밀번호가 다를 수 있습니다 (…)` | 이전에 다른 비밀번호로 setup 했어요 | 처음 정한 비밀번호로 다시 실행. 기억나지 않으면 코디네이터에게 |
| 웹 로그인에서 “이메일 또는 비밀번호가 맞지 않아요.” | 로그인 정보가 달라요 | setup 때의 이메일·비밀번호. 1분에 5번 넘게 틀리면 “요청이 너무 많아요. …”가 나오니 1분 뒤 다시 |
| 웹 로그인에서 “서버에 연결하지 못했어요. 연결을 확인하고 다시 시도해 주세요.” | API가 꺼져 있어요 | `corepack pnpm local:status`로 확인 후 `corepack pnpm local:start` |
| Safari 등 WebKit 계열 브라우저에서 로그인이 안 됨 | `Secure` 쿠키를 받지 않는 브라우저 | Chrome 또는 Firefox로 http://127.0.0.1:5180/ 열기 |

포트를 누가 쓰는지 확인하는 명령:

```sh
ss -ltnp | grep -E ':(3100|5180)\b'
```

## 3. 매일 쓰기

```sh
corepack pnpm local:status   # 지금 상태 한눈에 보기
corepack pnpm local:start    # API + 웹 시작 (필요할 때만 다시 빌드)
corepack pnpm local:stop     # API + 웹 종료 (스택·DB는 그대로)
corepack pnpm local:stack ps # 컨테이너 상태
```

### `local:status`

모두 정상이면 이렇게 나오고 종료 코드는 0이에요.

```text
[local] 로컬 상태 요약
[local]  대상: PostgreSQL 127.0.0.1:55442/planner · Vikunja http://127.0.0.1:3466
[local]  - 스택: 정상 (PostgreSQL, Vikunja)
[local]  - 마이그레이션: 최신
[local]  - 비밀 파일: 정상 (…/deploy/secrets/local)
[local]  - LLM 키 파일: 있음 (mode 600)
[local]  - Vikunja 토큰: 유효 (만료까지 …일 (YYYY-MM-DD))
[local]  - API: 정상 (http://127.0.0.1:3100)
[local]  - 웹: 정상 (http://127.0.0.1:5180/)
[local] 모든 항목이 정상입니다.
```

문제가 있으면 마지막 줄이 `확인이 필요한 항목: api, web`처럼 나와요(앱을 끈 상태라면 api·web이 나오는 게 정상이에요). 토큰·비밀번호·키 내용은 절대 출력하지 않아요.

### `local:stop`

```text
[local] API: 종료됨 (pid …, terminated).
[local] 웹: 종료됨 (pid …, terminated).
```

API·웹만 끄고 Docker 스택과 데이터는 건드리지 않아요. 20초 안에 안 꺼지면 강제로 끄고, 자기가 띄운 프로세스가 아니면 절대 신호를 보내지 않아요.

### 재부팅한 뒤

- PostgreSQL·Vikunja 컨테이너는 `restart: unless-stopped`라서 **Docker가 켜지면 스스로 다시 떠요.**
- API·웹은 다시 켜야 해요. **`corepack pnpm local:start` 한 번이면 돼요.** (남아 있던 오래된 PID 파일은 알아서 정리해요.) 그 뒤 브라우저에서 **다시 로그인**해요 — 지금 버전은 API를 다시 켤 때마다 로그인 세션이 사라져요.
- 예외: 재부팅 전에 `local:stack down`으로 직접 내렸다면 `corepack pnpm local:stack up`부터 해요.

### 새 코드로 업데이트할 때

```sh
corepack pnpm local:stop
git pull                      # 또는 코디네이터가 안내한 방법으로 코드 받기
corepack pnpm install         # 의존성이 바뀌었을 수 있어요 (바뀐 게 없으면 금방 끝나요)
corepack pnpm local:start     # 바뀐 소스가 있으면 알아서 다시 빌드해요
```

- `local:start`가 “마이그레이션이 최신이 아닙니다”라고 하면 `corepack pnpm local:setup`(같은 이메일·비밀번호)을 한 번 실행한 뒤 다시 `local:start` 해요.
- 강제로 다시 빌드하려면 `corepack pnpm local:start --rebuild`.
- 브라우저 탭은 새로 고침(F5) 하고 **다시 로그인**해 주세요(API를 다시 켜면 로그인 세션이 사라져요).

## 4. AI 사용 동의와 비용

### 동의 창

로그인한 뒤 AI에 아직 동의하지 않았다면 “**AI 계획 도움을 쓸까요?**” 창이 떠요. 내용은 이래요.

- **제공자**: OpenCode Go 게이트웨이 (DeepSeek 모델 · deepseek-v4.1-flash)
- **보내는 데이터**: 계획 마법사에 입력한 내용(제목·마감·설명·질문 답변)과 지금 단계에 필요한 작업 단계 정보만 보내요.
- **마스킹은 최선 노력이에요**: 자동으로 가리지만 모든 개인정보를 보장하지는 않아요(아래 ‘실제로 가리는 것’ 참고).
- **언제든 철회 가능**: AI 설정에서 바로 끌 수 있어요. 동의하지 않으면 직접 작성 모드로 동작하고 AI를 호출하지 않아요.

버튼은 두 개예요.

- “**AI 계획 도움 허용**” → 계획 마법사에서 AI를 써요.
- “**직접 작성 모드로 쓰기**” → AI를 전혀 호출하지 않아요. 창을 닫아도(Esc) 같은 뜻이에요. 동의하지 않은 동안에는 새로 고치거나 다시 로그인하면 이 창이 다시 떠요.

### 실제로 보내는 것과 보내지 않는 것

| 보내요 (동의했을 때만) | 보내지 않아요 |
|---|---|
| 계획 마법사의 제목·마감·설명, 질문 답변 | 로그인 비밀번호, Vikunja 토큰, API 키 파일, 서버 비밀 |
| AI가 만들 단계에 필요한 단계 정보, 비슷한 작업을 찾을 때 저장된 작업 템플릿(이름·단계 제목·결과물·완료 기준) | “AI에 보내기 허용”을 켜지 않은 노트, 계획에 연결하지 않은 노트 |
| **“AI에 보내기 허용”을 켜고 그 계획에 연결한 노트**의 제목과 관련 구간 일부(한 번에 최대 6KB, 가림 처리 후) | 집중 회고 메모, 일정·가용 시간·약속 전체 |

**실제로 가리는 것**(보내기 전에 자동으로 `[REDACTED_…]`로 바꿔요, `packages/llm/src/privacy.ts`):

- 이메일 주소
- 전화번호(국내 형식, +82 국제 형식 포함, 전각 숫자·특수 공백 섞인 것도)
- 주민등록번호
- API 키처럼 생긴 값

**가리지 못하는 것**: 이름, 주소, 계좌번호, 일부러 바꿔 쓴 이메일(예: ‘a 골뱅이 b’) 같은 것. 이런 정보는 마법사나 AI 허용 노트에 적지 마세요.

> 참고: 동의 창 문구에는 “이메일·전화번호·계좌번호 형식은 가려서 보내지만”이라고 되어 있는데, 현재 코드는 **계좌번호를 가리지 않아요**(가리는 것은 위 네 가지). 노트 편집기 안내 문구(“이메일·전화번호·주민등록번호·API 키처럼 보이는 값은 가려서 보내지만…”)가 실제 동작과 맞아요. 이 차이는 코디네이터에게 보고했어요.

노트를 AI에 보냈다면 그 노트 화면의 “**AI 근거 사용 이력**”에 언제·어떤 구간(해시)·얼마나(크기) 보냈는지 남아요. 보낸 글 자체는 저장하지 않아요.

### 예산

- 기본 상한: **하루 $0.20, 한 달 $5.00** (보수적으로 잡은 값).
- 바꾸는 곳: 왼쪽 메뉴 “**AI 설정**” › “예산” › “하루 상한 (USD)”, “한 달 상한 (USD)” › “**예산 저장**”. 저장하면 “현재 상한: 하루 …, 한 달 …”으로 보여요.
- 비용은 사용한 토큰 × 단가로 계산해요. 코디네이터가 실제로 재어 보니 **단계 초안 1회 생성에 약 $0.002–0.003**이었어요. 기본 하루 상한이면 하루 수십 번 쓸 수 있는 정도예요.
- 같은 OpenCode Go 계정 한도를 개발 작업과 함께 써요. 그쪽 한도에 걸리면 잠시 AI가 안 될 수 있어요(그때도 직접 작성으로 계속할 수 있어요).

### 동의하지 않았거나 예산을 넘으면

- 계획 마법사는 그대로 쓸 수 있어요. 질문은 규칙대로 나오고, 단계 초안 대신 **기본 3단계 초안(준비 → 작업 → 검토)**이 나와서 직접 고치면 돼요.
- 예산 한도에 닿으면 “AI 예산 한도에 닿았어요. 직접 작성으로 계속할 수 있어요.”, AI를 쓸 수 없을 때는 “**AI 도움 없이 계속할 수 있어요**” 안내와 “**직접 작성으로 전환**” 버튼이 나와요. 유료 호출은 더 하지 않아요.
- 일정 계산·오늘·집중·재계획·노트는 AI와 상관없이 모두 동작해요.

### 나중에 바꾸기

“AI 설정” 화면에서

- 꺼져 있으면 “직접 작성 모드” 표시와 “**AI 계획 도움 켜기**” 버튼,
- 켜져 있으면 “AI 계획 도움 켜짐” 표시와 “**동의 철회 (직접 작성 모드로 전환)**” 버튼이 있어요.

## 5. 둘러보기

E2E 시험(E2E-1~6)과 같은 순서로, 실제로 써 보면서 확인할 흐름이에요. 각 단계는 **어디를 누르는지 → 무엇이 보이는지 → 무엇을 판단할지** 순서로 적었어요.

### 화면 구성 먼저 보기

- 왼쪽 메뉴(넓은 화면): **하루** — 오늘, 인박스, 프로젝트, 노트, 알림 / **계획** — 계획 세우기, 일정안 만들기, 재계획 제안, 내 패턴, 약속, 가용 시간 / **설정** — AI 설정, 레이아웃 / 아래쪽에 검색, 도움말, 로그아웃.
- 좁은 화면(창을 줄였을 때): 아래쪽 메뉴에 오늘 · 인박스 · ＋(새 작업) · 계획 · “더 보기”.
- 키보드 단축키(입력란 밖에서): `n` 새 작업, `t` 오늘, `f` 집중 세션, `/` 검색, `?` 이 도움말, `Esc` 대화상자 닫기.

### ① 인박스에 적기 (E2E-1)

- **어디**: “인박스” → 위쪽 입력란(“무엇을 해야 하나요?”) → “**작업 추가**” (또는 Enter).
- **보이는 것**: 목록에 작업이 생기고 “할 일” 상태. 각 작업에 “수정”, “완료”, “삭제”. 삭제하면 잠깐 “실행 취소”가 떠요.
- 같은 작업을 두 곳(예: 탭 두 개, 또는 Vikunja 화면)에서 고치면 “**다른 곳에서 이 작업이 바뀌었어요**” 창이 떠요. “서버 버전 불러오기” 또는 “내 수정으로 덮어쓰기” 중 골라요.
- 인터넷이 끊기면(=API에 못 닿으면) “오프라인이에요. 저장해 둔 데이터를 보여 드리고 있어요. …” 배너가 뜨고 편집이 잠겨요.
- **판단**: 떠오른 일을 적는 게 충분히 빠른가요? 목록이 읽기 쉬운가요?

### ② 계획 마법사: 기본정보와 질문 (E2E-2)

- **어디**: 왼쪽 “**계획 세우기**”.
- **1단계 · 기본정보**: “제목”(필수), “마감 (선택, 현지 시간)”, “설명 (선택)” → “**다음**”. (“파일 이름”은 아직 업로드가 안 돼요.)
- AI를 허용했다면 “**AI가 비슷한 작업을 찾고 있어요 · 보통 10–20초**” 대기 패널이 나와요.
- **2단계 · 유형 확인**(비슷한 이전 작업이 있을 때만): “이전 작업과 비슷해요”, 판단 근거와 함께 “이번에도 같은 유형인가요?” → “예” / “아니오”.
- **3단계 · 질문**: 한 번에 최대 5개. 각 질문에 “답변” 입력 또는 “**모름**” / “**건너뛰기**”. 이미 입력한 마감은 다시 묻지 않아야 해요.
  - 예: “무엇을 결과물로 만들어야 하나요?”, “규모가 어느 정도로 느껴지나요? (작음, 보통, 큼)”, “지금까지 얼마나 해 두었나요?”, “이 일에 쓸 수 있는 시간이 이미 정해져 있나요?”
  - 모름/건너뛰기를 누르면 아래 “**가정**” 목록에 어떻게 처리했는지 보여요(예: “P90 추정치 사용”, “마감 없음으로 가정”, “확인 안 됨 (승인 전에 직접 확인)”).
  - 위쪽 “일시정지”/“재개”, “취소”, 아래쪽 “**직접 작성으로 전환**”은 언제든 쓸 수 있어요.
- **판단**: 질문이 꼭 필요한 것만인가요? 이미 말한 것을 또 묻지는 않나요? 질문 문구가 자연스러운가요?

### ③ AI 단계 초안 → 고치기 → 승인

- 질문을 마치면 “**AI가 단계를 만들고 있어요 · 보통 30초–1분**” 패널이 나와요. 경과 시간이 표시되고, “다른 화면으로 가거나 새로 고쳐도 AI 작업은 계속돼요. 돌아오면 이어서 보여 드릴게요.” 기다리기 싫으면 “취소” 또는 “직접 작성으로 계속”.
- **4단계 · 단계 초안**: 단계마다 “제목”, “산출물”, “완료 기준”, “종류”(준비/작업/검토/버퍼), “P50 (분)”, “P90 (분)”, “선행 단계”. “단계 추가”, “단계 삭제”, “초안 저장”, “**초안 승인**”.
  - 규칙: 단계 3–12개, P50 ≤ 240분, P90 ≥ P50, 검토·버퍼 단계 1개 이상, 순환 없는 선행 관계. 어기면 해당 칸에 이유가 떠요.
  - P50은 ‘보통 이 정도’, P90은 ‘넉넉히 잡으면 이 정도’ 시간이에요.
- **승인하면**: “**초안 승인 완료** · 단계 초안을 승인해서 작업을 만들었어요.” 단계들이 인박스 작업으로 생겨요(Vikunja에도). “인박스에서 만든 작업 보기”, “프로젝트 보기”.
  - 이 화면의 “다음 단계: 일정안(곧 지원)” 문구는 예전 문구예요. **일정안은 이미 “일정안 만들기”에서 만들 수 있어요**(아래 ⑤).
- **판단**: 단계 나누기가 실제로 내가 할 순서와 맞나요? P50/P90 추정이 현실적인가요? 한국어 단계 이름이 자연스러운가요? 기다리는 시간이 견딜 만한가요?

### ④ 가용 시간과 약속 (일정안 만들기 전에)

- **가용 시간**(왼쪽 “가용 시간”): “시간대”(IANA, 예: Asia/Seoul), “**주간 규칙**”(요일·시작·종료·종류 “업무”/“집중”, “주간 규칙 추가”), “**예외**”(날짜별 “쉼”/“추가”, “예외 추가”), “**집중 설정**”(“하루 최대 집중 (분)”, “쉬기 전 최대 연속 집중 (분)”, “휴식 길이 (분)”, “하루 시작”, “하루 끝”, “추정 기준” P50 (보통)/P90 (안전)) → “**가용 시간 저장**” → “가용 시간을 저장했어요 (버전 N).”
- **약속**(왼쪽 “약속”): 계획이 피해 가야 하는 고정 일정. “제목”(예: 세미나, 출퇴근, 가족 저녁), “시작 (현지 시각)”, “종료 (현지 시각)”, “매주 반복할 요일” → “반복 일정 미리보기” 확인 → “**약속 만들기**”.
- **판단**: 내 실제 하루를 입력하기 쉬운가요? 기본값이 내 생활과 맞나요?

### ⑤ 일정안 후보 만들기와 비교 (E2E-3)

- **어디**: 왼쪽 “**일정안 만들기**” → “새 일정안”.
  - “범위”: 계획할 작업을 체크해요(③에서 만든 단계 작업들).
  - “기간”: “시작일”~“종료일”(기본 오늘부터 14일, 최대 366일).
  - “정책”: “**앞당겨 끝내기**”(일찍 끝내서 마감 여유 확보), “**고르게 나누기**”(날마다 고르게), “**집중 시간 묶기**”(긴 집중 시간, 전환 최소화). 정책마다 후보가 하나씩 만들어져요.
  - “**후보 만들기**”.
- **일정안 비교 화면**: 후보 카드마다 “배치 가능” 또는 “배치 불가 · N 부족”, 지표(총 집중 시간, 최소 여유, 하루 최대 부담, 하루 평균 부담, 작업 전환, 바뀐 블록, 부족한 시간, P90 충족률), “계산 근거”.
  - **다양성 안내**: 후보가 서로 너무 비슷하면 하나로 합쳐요. 예: “서로 다른 일정안 2개를 남겼어요. 후보 3개 중 1개는 너무 비슷해서 뺐어요.” / “후보 3개가 모두 서로 충분히 달라요.” 후보가 3개보다 적은 건 정상이에요.
  - “주간 보기”(“이전 주”/“다음 주”): 블록을 끌어서 옮기거나 크기를 바꿀 수 있어요. 키보드로는 ↑/↓로 5분씩 이동, Shift+↑/↓로 길이 조절. 문제가 있으면 “일정 규칙에 맞지 않는 부분”이 보여요. “편집 되돌리기”, “다시 만들기”.
- **확정**: “**이 일정으로 확정**” → “일정안을 확정했어요 (버전 N).”, “**일정 확정 완료**”(버전·블록·가용 시간 버전·만든 주체) → “오늘 열기”.
  - 그사이 가용 시간이 바뀌었다면 “다른 곳에서 가용 시간이 바뀌었어요.” → “**일정안 다시 만들기**”로 최신 상태 기준으로 다시 만들어요.
- **판단**: 후보끼리 정말 다른 선택지인가요? 지표가 고르는 데 도움이 되나요? 배치가 내 생활 리듬에 맞나요? 생성 속도는 어떤가요?

### ⑥ 오늘과 집중 (E2E-4)

- **어디**: 왼쪽 “**오늘**”(단축키 `t`).
- **하루 한눈에 보기**: 여유·계획·블록 수, “위험도: 낮음/보통/높음”과 이유. “**오늘 계획 수락**”, “**재계획 요청**”.
- **블록 카드**: 순서, “다음 차례”, 시간, “여유 …”, “위험도 …”. 버튼 “**집중 시작**”, “**축소**”, “**재배치**”, “**블록 고정**”.
  - “축소” → “새 길이 (분)” → “축소 미리보기” → “**제안 미리보기**”(“… 축소 제안이에요. 승인하기 전에는 아무것도 바뀌지 않아요.”) → “제안 승인”.
  - “재배치” → 같은 미리보기 → “제안 승인”.
- **집중 화면**: “집중하는 중”, 타이머, “계획 1시간 30분 중 0분 집중”. “**일시정지**”(Space) / “다시 시작”, “**완료**”(Enter), “**몰입 모드**”(화면을 단순하게), “오늘로 돌아가기”. 동시에 하나의 세션만 진행할 수 있어요.
  - 세션 도중 네트워크가 끊겨도 타이머는 이 기기에서 계속 돌아가고, 다시 연결되면 기록을 자동으로 올려요.
- **회고**: 완료하면 “**이번 세션은 어땠나요?**” → 결과(“완료”/“일부만”/“막힘”) 한 번만 눌러도 돼요. 이유(“생각보다 컸어요” 등)와 “메모 (선택, 나만 볼 수 있어요)”는 선택 → “회고 저장” → “**추정 피드백**: 예상 … · 실제 …”.
- **판단**: 오늘 할 일이 한눈에 보이나요? 축소·재배치 제안이 합리적인가요? 집중 화면이 방해 없이 쓰기 좋은가요? 회고가 부담스럽지 않나요?

### ⑦ 블록 고정

- **어디**: “오늘”의 블록 카드, 또는 “일정안 비교” 화면 아래 “**확정된 일정**” 목록.
- **동작**: “**블록 고정**”을 누르면 버튼이 “**고정 해제**”로 바뀌고(눌림 상태: 스크린리더에서는 `aria-pressed`가 true), “블록을 고정했어요. 재계획해도 이 블록은 옮기지 않아요.”가 떠요. 고정된 블록은 “축소”·“재배치”가 잠겨요. 다시 누르면 “고정을 풀었어요. 다음 재계획에서 이 블록을 옮길 수 있어요.”
- 이미 시작했거나 끝난 블록은 바꿀 수 없어요(“이미 시작했거나 끝난 블록은 고정을 바꿀 수 없어요. …”). 재계획 제안 화면에서는 “고정됨” 배지로만 보여요.
- **판단**: ‘이건 절대 옮기지 마’라는 뜻이 버튼 이름과 상태로 잘 전달되나요?

### ⑧ 재계획 제안 (E2E-5R)

- **언제 생기나요**: 마감 위험(P90 기준 여유 부족), 새 약속과 겹침, 일찍 끝나서 남는 시간, 그리고 내가 직접 “재계획 요청”을 눌렀을 때. 자동 감지는 몇 분마다(최대 5분 간격) 돌아요.
  - 직접 해 보기: ⑤에서 확정한 블록과 겹치는 약속을 하나 만들고(④의 “약속” 화면) 몇 분 뒤 “오늘”을 새로 고쳐요.
- **보이는 것**: “오늘” 위에 “**재계획 제안 1개가 기다리고 있어요**” · “약속과 겹치는 블록이 있어요. 승인하기 전에는 아무것도 바뀌지 않아요.” → “**제안 확인하기**”. 알림에도 “다시 짠 계획 제안이 준비됐어요”.
- **제안 화면**: “왜 제안했나요”, “영향받는 작업”, “핵심 지표”(지금 vs 제안: 마감 여유, 계획된 집중 시간, 바뀌는 블록 수와 상한), “**바뀌는 블록**”(옮김/줄어듦/늘어남/추가/빠짐, 이전·이후), “고정된 블록 (바뀌지 않아요)”. 버튼 “**승인**” / “**거절**”.
  - 승인: “제안을 승인했어요. 새 일정이 반영됐어요.” 바뀌는 블록만 바뀌어요.
  - 거절: “**이 제안을 거절할까요?**” → “거절 이유 (선택, 나만 볼 수 있어요)” → “거절하기”. 같은 이유의 제안은 24시간 동안 다시 만들지 않아요.
- **억제 규칙**: “재계획 제안은 하루 최대 2번이고, 거절한 이유는 24시간 동안 다시 제안하지 않아요.” 직접 요청한 제안을 거절하면 24시간 동안 직접 요청도 막혀요(“지금은 재계획을 더 요청할 수 없어요. … 뒤(…)에 다시 요청할 수 있어요.”). 제안은 24시간이 지나면 만료돼요.
- 모든 제안은 왼쪽 “재계획 제안”에서 “기다리는 제안” / “지난 제안”으로 볼 수 있어요.
- **판단**: 제안이 너무 자주/드물게 오나요? ‘최소한만 고친다’는 약속이 지켜지나요? 이유 설명이 이해되나요?

### ⑨ 노트와 노트를 근거로 한 초안 (E2E-6 노트)

- **노트 만들기**: 왼쪽 “노트” → “**새 노트**”. “제목”, “내용 (Markdown)”, 보기 방식(편집/미리보기/나란히), “민감도”(P2 · 일반 노트 (기본) / P1 · 개인 일정 정보), “**AI에 보내기 허용**” 스위치(기본 꺼짐) → “노트 만들기”.
  - 미리보기는 링크를 바로 열지 않고 주소만 보여 주며, 이미지는 불러오지 않아요.
- **연결**: 노트의 “연결 대상” → “연결 추가”로 프로젝트·작업에 연결해요. 계획 목표에는 마법사에서 연결해요.
- **노트를 근거로 초안 만들기**: “계획 세우기”의 질문 단계 아래 “**이 계획에 참고할 노트**” → “노트 연결” → 노트 고르기. “AI에 보내기 허용”을 켠 노트만 실제로 전송돼요(“AI 전송 허용” / “AI에 보내지 않음” 표시).
  - 단계 초안에 “**이 초안의 노트 근거**”가 보여요. “사실”(노트에 적힌 내용)과 “추론”(AI가 짐작한 내용)을 나눠 보여 주고, 노트 속 글은 지시가 아니라 자료로만 보여 줘요.
  - 노트 화면 “**AI 근거 사용 이력**”에서 실제로 보낸 기록(“계획 단계 나누기”, “성공”, 구간 해시·크기)을 확인할 수 있어요.
- **관련 노트**: 집중 화면 오른쪽 “관련 노트”에 지금 하는 일과 연결된 노트가 최대 3개 보여요.
- 노트 검색: “노트 검색”(단어 앞부분으로 찾아요, 예: “논문”으로 “논문을”도). 작업 상세 화면의 “설명을 노트로 승격”으로 작업 설명을 노트로 옮길 수도 있어요.
- 노트는 OhMyDate에만 저장되고 Vikunja와 동기화하지 않아요.
- **판단**: 노트가 초안 품질을 실제로 높였나요? 무엇이 전송되는지 충분히 투명한가요?

### ⑩ 적응형 레이아웃·내 패턴·설정 (E2E-6 레이아웃)

- **레이아웃 자동 전환**: 집중을 시작하면 화면 배치가 “집중”으로 바뀌고 “**레이아웃이 바뀌었어요**” 알림에 “되돌리기” / “자동 전환 끄기”가 나와요. 마감 위험이 있으면 “마감 위험이 있어요”(“재계획 제안 보기” / “확인했어요”), 저녁 8시 이후 회고 안 한 세션이 있으면 “오늘 회고할 세션이 있어요” 패널이 나와요.
- **레이아웃 설정**(왼쪽 “레이아웃”): “상황에 맞춰 화면 배치를 자동으로 바꾸기”(바뀐 뒤 10분은 그대로, 입력 중엔 안 바꿈), “지금 배치 고정하기 (…)”, “배치가 정해지는 순서”. 주 메뉴는 늘 그대로예요.
- **내 패턴**(왼쪽 “내 패턴”): 회고에서 배운 추정 습관. “반영된 기록”, “신뢰도”, 작업 유형별 비율(실제 ÷ 예상), 기록마다 “통계에 포함” 스위치, “모든 학습 기록 지우기”. 처음에는 “아직 배운 내 패턴이 없어요”가 정상이에요(템플릿 기본값, 없으면 AI 추정 × 1.3).
- **알림**(왼쪽 “알림”): 리마인더와 하루 요약. “푸시 알림 켜기”는 선택이에요.
- **판단**: 화면이 저절로 바뀌는 게 도움이 되나요, 거슬리나요? 내 패턴 설명이 이해되나요?

### 살펴볼 것 (체크리스트)

### 보내는 양식

한 건에 하나씩, 아래 양식을 복사해서 코디네이터에게 보내 주세요.

```text
[날짜·시간] 2026-11-13 21:30
[화면] 예: 일정안 비교 / 계획 마법사 4단계 / 오늘
[한 일] 예: 작업 3개로 후보 만들기 → '고르게 나누기' 확정
[기대한 것] 예: 저녁 7시 이후로만 배치
[실제로 일어난 것] 예: 오후 2시에 블록이 생김. 화면 문구: "…"
[얼마나 중요한가] 막힘 / 불편 / 사소함 / 제안
[스크린샷] 선택 (비밀번호·키·토큰·개인정보가 보이지 않게)
[local:status 결과] 오류일 때만 (비밀값은 원래 출력되지 않아요)
```

- 오류였다면 `corepack pnpm local:status` 출력과, 가능하면 `.local/logs/api.log` **마지막 몇 줄**을 붙여 주세요. 로그에는 노트 본문·프롬프트·토큰이 남지 않게 되어 있지만, 보내기 전에 한 번 훑어봐 주세요.
- **절대 넣지 말 것**: API 키, `deploy/secrets/` 안의 파일 내용, 비밀번호, Vikunja 토큰, 남에게 보여 주기 싫은 개인정보.

## 7. 알려진 제한

- **GU-1 범위**: [1장 표](#gu-1은-무엇을-위한-단계인가요)의 ‘아직 아니에요’ 항목은 지금 버전에 없어요. 특히 작업 저장소는 아직 Vikunja이고(M7에서 교체 예정), 이 노트북 밖에서는 접속할 수 없어요.
- **브라우저**: API가 `Secure` 쿠키를 써요. Chrome·Firefox는 `http://127.0.0.1`을 안전한 주소로 취급해서 잘 되지만, **Safari와 WebKit 계열 브라우저는 쿠키를 버려서 로그인이 되지 않아요.** 주소는 `http://127.0.0.1:5180/` 그대로 쓰세요.
- **로그인 유지**: 로그인 세션은 DB에 저장돼서 **`local:stop`/`local:start`, 재부팅, 업데이트, 토큰 교체(`--rotate-token`) 뒤에도 로그인이 유지돼요**(FU-92). 마지막으로 쓴 때부터 14일 동안 쓰지 않았거나 “로그아웃”을 누르면 다시 로그인해야 해요. 비밀번호 재설정 화면은 없어요 — 잊어버리면 코디네이터에게 요청해 주세요.
- **Vikunja 화면(선택)**: http://127.0.0.1:3466 에서 Vikunja 원래 화면을 볼 수 있어요. 계정은 `local:setup`이 만들었고, setup이 출력한 사용자 이름(`local-…`)과 같은 비밀번호로 로그인해요. 꼭 쓸 필요는 없고, 작업은 OhMyDate에서 다루는 걸 권해요(두 곳에서 동시에 고치면 충돌 확인 창이 떠요).
- **Vikunja 회원가입**: 로컬 Vikunja는 회원가입이 켜져 있지만 127.0.0.1에서만 열려 있어요. 포트를 다른 기기에 열거나 포워딩하지 마세요.
- **Vikunja API 토큰**: OhMyDate가 Vikunja에 접근하는 토큰은 **365일** 동안 유효해요. 남은 기간은 `local:status`의 “Vikunja 토큰: 유효 (만료까지 N일 …)”로 확인해요. 바꾸려면:

  ```sh
  corepack pnpm local:setup --rotate-token   # 이메일·비밀번호를 다시 물어요. 새 토큰 발급 후 이전 토큰 삭제
  corepack pnpm local:stop
  corepack pnpm local:start                  # API가 새 토큰을 읽어요
  ```

- **AI 마스킹 문구 차이**: [4장](#실제로-보내는-것과-보내지-않는-것) 참고. 계좌번호는 가리지 않아요.
- **화면 문구 차이(작성 시 확인)**:
  - 계획 마법사 단계 표시의 “5 일정안 · 곧 지원”과 완료 화면의 “다음 단계: 일정안(곧 지원)”은 예전 문구예요. 일정안은 “일정안 만들기”에서 만들어요.
  - “검색”(`/`) 창은 아직 “검색은 다음 단계에서 지원해요” 안내만 있어요. 노트 검색은 “노트” 화면에서 돼요.
  - 1단계의 “파일 이름”은 이름만 적을 수 있고 업로드는 아직 안 돼요.
- **데이터 초기화·복원**은 코디네이터 작업이에요. `local:stack down`은 볼륨을 지우지 않아요.
