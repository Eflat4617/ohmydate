ADR-023 amendment (regression bullet) and the harness comment claim it covers "the answer arrives and the owner changes before the awaiting code resumes".   [LOW] The transport captures the owner signal when `this.client.X` runs, not when the method is entered
    Evidence: apps/web/src/api/client.ts:483,502 (update/deleteCommitment await resolveCommitmentVersion first); likewise task/availability/plan/intake methods without expectedVersion. The signal is taken one or more microtasks after the caller's turn, or after a version GET. Production owner switches arrive as storage events (macrotasks), so this window cannot be reached in practice. ADR decision 5 ("same synchronous segment as the method call") is slightly overstated.
    Suggestion: wording fix, or capture the signal at method entry.
