  [HIGH] 1. local:stop kills whatever PID is in the pid file (no identity check); local:start trusts the same file
    Evidence: scripts/local/stop.mjs:28-57 (process.kill(-pid) then pid, SIGTERM, SIGKILL after 15 s) and scripts/local/start.mjs:281-283, 295-297 (processAlive(pid) only). Repro: wrote the PID of an unrelated `setsid sleep 600` into <run>/api.pid, ran `node scripts/local/stop.mjs` -> "[local] API: 종료됨 (pid 2410487, terminated)", exit 0, the sleep was dead. Because the signal goes to -pid, a recycled PID that is a group leader loses its whole process group. Stale files are easy to get: .local/run survives reboot/crash, and a failed start leaves api.pid pointing at a dead PID (reproduced, see finding 4). The same stale PID makes local:start print "API가 이미 실행 중입니다", skip the spawn and time out after 60 s.
    Required change: store an identity next to the PID (e.g. /proc/<pid>/stat start time plus expected cmdline, or a random marker passed to the child) and verify it in stop.mjs and start.mjs before signalling or skipping; on mismatch treat the file as stale (delete it, never signal). Remove pid files when start fails. Add a negative test: a foreign live PID in the pid file is not signalled and is not reported as running.
