COORDINATOR'S JUDGMENT (recorded in the ledger): yes to both. Vikunja only holds tasks/projects, forces every task-level feature through a second model plus a reconciler, and cannot be bundled in an app. The current core cannot become a desktop app as it is: it needs PostgreSQL (jsonb in 183 places, gist in 50, advisory locks), Node 24 and docker, and a large share of it is server machinery one person on one laptop does not need (login, sessions, CSRF, rate limits, leader locks, multi-owner isolation, Vikunja reconcile). Measured today: server-side TypeScript ≈ 56k lines (api 30.4k, scheduler 7.2k, llm 6.0k, contracts 5.2k, provider-vikunja 3.9k, domain 2.3k, provider-native 1.0k) with ≈ 56k lines of tests; the web app is another 56k and STAYS (Vue, shown in the app's webview).

FIXED DECISIONS (argue with one only if you find a concrete reason in the code; then say so in the report instead of silently changing it)
 1. Target: a Linux desktop app, one user, no server to install. Shell = Tauri 2; UI = the existing Vue app (`apps/web`) unchanged in structure, loaded in the webview. A separate task builds the shell; you design for it.
 2. The core is a Rust library plus a small binary. It serves THE SAME HTTP contract the web app already speaks (`packages/contracts`, `openapi.json`) on 127.0.0.1 (random port + per-launch secret, or the shell's custom protocol — decide and justify). Reason: the web client, the Playwright E2E suite and the contract tests keep working, and the core can run headless for tests. Routes that only exist for the server shape (login, logout, push subscriptions, e2e reset, …) are dropped or stubbed: list each.
 3. Storage: SQLite (one file under the XDG data dir, WAL). No PostgreSQL, no docker. Constraints PostgreSQL enforced (exclusion, ranges) move into code with tests.
 4. Vikunja is removed. Tasks, projects and dependencies are native tables. `packages/provider-vikunja` and `services/api/src/adapters/vikunja` are not ported.
 5. One local owner. No login, no sessions, no CSRF. Keep ETag / If-Match and Idempotency-Key semantics (the web client depends on them and offline replay needs them).
 6. Secrets (LLM key, Google refresh token, OAuth client) live in the OS keyring (Secret Service) with a file fallback; never in the database in plaintext, never in logs.
 7. The scheduler is PORTED to Rust, not wrapped: with the TypeScript scheduler as the oracle (it is pure and seeded — differential tests over generated inputs must match exactly), and its property tests ported. Time arithmetic uses a Temporal-like crate with IANA zones (`jiff` is the default choice; verify licence and DST behaviour against the cases in `packages/scheduler/test`).
 8. Prompts and JSON schemas of `packages/llm` stay the single source (read as files / embedded at build); the Rust side validates with a JSON-schema crate and keeps the budget, consent, masking and logging rules.
 9. The TypeScript core (`services/api`, `packages/*`) is frozen for features from the cut-over plan onward (bug fixes only) and stays the reference until the Rust core passes the parity suites; then one cut-over with a one-time import of the user's existing data (the app already has an owner export: `/exports`; prefer importing that over reading the old databases directly).
10. Desktop-only capabilities the plan must place: tray icon, native notifications for block reminders and the morning summary, autostart, background Google sync with the window closed, single-instance, backup of the data file.
11. Licences: MIT / Apache-2.0 / BSD / ISC crates only without review (AGENTS.md); anything else is listed for the user.
