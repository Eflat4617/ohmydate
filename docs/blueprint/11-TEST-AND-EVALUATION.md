# 11. 테스트·평가 전략

## 1. 계층과 도구 [결정 제안, M1-01에서 확정]
| 계층 | 도구 | 범위 | 실행 위치 |
|---|---|---|---|
| 타입/정적 | `tsc --noEmit`(strict), ESLint, 경로 경계 검사(`dependency-cruiser`) | 전체 | G1 워커, G3 |
| 단위 | Vitest | domain, scheduler, estimator, ui-policy, 권한 | G1 |
| 속성 | fast-check | scheduler 하드 제약, DAG, 시간대 | G1(1k), G3(10k) |
| 통합 | Vitest + 실제 PostgreSQL(GD-1 결정 방식) | 리포지토리, TX, outbox, 승인 원자성 | G3 |
| 계약 | testkit 스위트 | TaskRepository 3구현, OpenAPI 스냅샷 | G3 |
| E2E | Playwright | 핵심 흐름(아래) | G4 |
| 접근성 | @axe-core/playwright | 주요 화면 | G4 |
| AI 평가 | 녹화 fixture + 오프라인 평가 스크립트 | 05 지표 | 마일스톤별 |
| 성능 | 벤치 스크립트 | scheduler p95, API p95 | G4 |

**규칙:** 테스트 삭제/완화로 통과 금지. skip은 사유·이슈 링크 필수. 실제 외부 API 호출 금지(CI) — LLM은 FakeLlm.

## 2. 마일스톤 E2E 시나리오
- E2E-1(M1): 로그인 → 작업 생성 → Vikunja API로 존재 확인 → 수정 → 다른 탭에서 수정 후 412 처리 → 완료.
- E2E-2(M2): 신규 과제 → 질문(이미 입력한 마감은 질문 안 함) → 초안 편집 → 승인 → Task 생성.
- E2E-3(M3): 3안 비교 → 편집 → 승인 → 다른 세션에서 commitment 추가 후 승인 재시도 412 → 재생성.
- E2E-4(M4): Today → 세션 시작/일시정지/완료 → 피드백 → 알림 dedupe.
- E2E-5(M5): 지연 → 재계획 제안 1회 → 승인 → changedBlocks 최소.
- E2E-6(M6): 노트 연결 → AI 근거 표시 → 인젝션 문서 무시 → 레이아웃 focus 전환·undo.
- E2E-7(M7): 이전 리허설 → 검증 리포트 → provider 스위치 후 E2E-1~5 재실행.
- 장애 주입: LLM 503, Vikunja 다운, 오프라인 클라이언트.

## 3. AI 평가 지표 [초기 목표]
| 지표 | 측정 | 목표 |
|---|---|---|
| 중복 질문률 | 이미 제공된 필드 질문 / 전체 | 0% (결정론 필터) |
| 질문 적합성 | 평가 세트 20과제 수동 라벨 | ≥ 80% 유용 |
| 단계 누락 | 기준 단계 대비 recall | ≥ 0.8 |
| 환각 참조 | hallucinated_ref / 실행 | < 2%, 반영 0 |
| 불가능 탐지 | F1 유형 케이스 | 100% 탐지(결정론) |
| 유사 유형 오탐 | 라벨 세트 | < 20% |
| 인젝션 방어 | 20종 문서 | 지시 수행 0 |

## 4. 성능·운영
홈서버 메모리 실측(M1 종료), 3안 생성 p95, 백업/복구 리허설(M7), 디스크 사용 증가율.

## 5. UX 지표 수집(로컬 집계, 외부 전송 없음)
계획 승인율, 제때 완료율, 추정 오차(MAPE), 주간 재계획 수·거절률, 알림 수/무시율, 일정 편집 횟수, 주간 활성 일수.

## 6. 개인정보 테스트
로그 redaction 테스트(노트 본문 문자열이 로그에 없음), 내보내기 완전성, 계정 삭제 후 행 0, LLM 전송 페이로드 스냅샷(마스킹 확인).

## 7. 품질 게이트 매핑 (명세 E.3)
G0 설계(본 문서 승인) · G1 워커 내부(타입·린트·단위·변경 범위) · G2 Sol 리뷰 · G3 통합(병합 후 전체 단위+통합+계약) · G4 마일스톤 E2E · G5 스테이징/운영(백업·복구·보안 + 사용자 승인).
